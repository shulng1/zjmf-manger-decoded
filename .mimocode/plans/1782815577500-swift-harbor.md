# 授权码验证逻辑移除计划

## 概述

本项目（ZJMF 智简魔方财务系统 v3.5.8）的授权码验证逻辑分散在约 **20+ 个文件** 中，涉及远程服务器通信、RSA 解密、中间件拦截、内联检查等多个层面。目标是**彻底移除所有授权码验证逻辑**，使系统始终以"专业版"身份运行，所有功能无条件可用。

---

## 第一阶段：核心函数层（app/common.php）

**文件：** `app/common.php`

### 1.1 修改 `is_profession()` (line 167)
- **当前行为：** 解密授权 blob 并返回 `edition` 值 (0=免费, 1=专业)
- **修改为：** 直接 `return 1;`
- **影响：** 全局所有依赖 `is_profession()` 判断专业版的功能都将解锁

### 1.2 修改 `compareLicense()` (line 3148)
- **当前行为：** POST 到 `https://license.soft13.idcsmart.com/app/api/auth_complete`，存储返回的授权 blob
- **修改为：** 直接 `return true;` (或空操作)
- **影响：** 不再联系远程授权服务器

### 1.3 修改 `de_authorize()` (line 185)
- **当前行为：** 使用 RC4 + RSA 解密授权 blob
- **修改为：** 直接返回一个伪造的合法授权数组：
  ```php
  return [
      'ip' => $_SERVER['SERVER_ADDR'] ?? '',
      'domain' => $_SERVER['HTTP_HOST'] ?? '',
      'license' => configuration('system_license') ?? '',
      'installation_path' => CMF_ROOT,
      'last_license_time' => time(),
      'license_error_time' => 0,
      'edition' => 1,
      'status' => 'Active',
      'suspend_reason' => '',
      'facetoken' => '',
      'app' => [],  // 空数组即可，不再需要逐个授权
      'due_time' => '2099-12-31 23:59:59',
      'auth_due_time' => '2099-12-31 23:59:59',
      'create_time' => date('Y-m-d H:i:s'),
  ];
  ```
- **影响：** 所有调用 `de_authorize()` 的地方都将获得合法授权数据

### 1.4 修改 `de_systemip()` (line 201)
- **当前行为：** 解密远程服务器返回的加密 IP
- **修改为：** 直接返回 `$_SERVER['SERVER_ADDR'] ?? ''`
- **影响：** IP 校验永远通过

### 1.5 修改 `pluginIdcsmartauthorize()` (line 7314)
- **当前行为：** 验证插件是否在授权的 app 列表中
- **修改为：** 直接 `return ["status" => 200];`
- **影响：** 所有插件授权检查通过

### 1.6 修改 `serverModuleIdcsmartauthorize()` (line 7342)
- **当前行为：** 验证服务器模块是否在授权的 app 列表中
- **修改为：** 直接 `return ["status" => 200];`
- **影响：** 所有服务器模块授权检查通过

### 1.7 修改 `zjmfhook()` (line 6679)
- **当前行为：** 在 line 6689-6713 中检查插件授权
- **修改为：** 删除 line 6689-6713 的 `if (in_array(lcfirst($pluginName) . "idcsmartauthorize", $methods)) { ... }` 整个代码块
- **影响：** 插件 hook 不再需要授权验证

### 1.8 修改 `putLicenseAfter()` (line 7102)
- **当前行为：** 免费版时禁用部分功能
- **修改为：** 直接 `return;` (空操作)
- **影响：** 更换授权码后不再禁用功能

### 1.9 修改 `throwEditionError()` (line 7117)
- **当前行为：** 免费版时抛出异常
- **修改为：** 直接 `return;` (空操作)
- **影响：** 不再因免费版抛出异常

### 1.10 修改 `recurseGetLastVersion()` (line 6934)
- **当前行为：** 根据授权码过滤升级版本
- **修改为：** 简化为直接返回，不过滤 beta 版本
- **影响：** 升级版本不再受授权码限制

## 第三阶段：内联授权检查（各控制器）

**统一修改策略：** 删除每个方法开头的整个授权解密和 `$app` 数组检查代码块，直接跳到业务逻辑（让 `$app` 相关检查永远通过）。

### 3.1 AdvancedOptionsController.php

- `create()` (line 101-122): 删除授权检查，`seniorConfig` 检查改为始终通过

- `deleteResult()` (line 391-412): 同上
- `addCondition()` (line 442-463): 同上
- `addResult()` (line 554-575): 同上

**修改方式：** 在每个方法中，删除从 `$zjmf_authorize = configuration("zjmf_authorize");` 到 `if (!in_array("seniorConfig", $app))` 检查之间的所有代码（约 20 行），并删除该 `in_array` 检查行本身。

## 验证方案

1. **后台登录测试：** 访问后台登录页面，输入管理员账号密码，确认可以正常登录
2. **后台功能测试：** 逐一测试以下功能，确认无授权错误：
   - 系统设置（`admin/system/info`, `admin/system/commoninfo`）
   - 产品管理
   - 订单管理
   - 高级配置选项（AdvancedOptionsController 的所有操作）
   - 发票管理（VoucherController）
   - 第三方登录管理（OauthController）
   - 消息批量发送
   - 应用商店
3. **前台测试：** 访问客户前台，确认页面正常加载
4. **安装流程测试：** 在新环境中测试安装流程，确认可以跳过远程授权验证
5. **版本切换测试：** 测试 stable/beta 版本切换功能
6. **升级测试：** 确认系统升级功能正常
7. **插件/模块测试：** 确认所有插件和服务器模块可以正常安装和使用
